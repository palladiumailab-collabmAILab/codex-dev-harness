# GPT-6 Astra profile

GPT-6 Astra で作業するときだけ使用するモデル固有ガイダンスです。

## Context discipline

- タスクに必要なファイルだけを選んで読む。編集前の全件走査や、無条件の設計文書読み込みを要求しない。
- root `AGENTS.md` の発火条件に一致した skill だけを読む。関連しない skill や補助資料を先読みしない。
- skill が複数の workflow を含む場合も、現在の判断に必要な節・補助資料だけを段階的に読む。
- 既存コード、近傍テスト、対象仕様から十分に判断できる場合、追加の説明文書を探すこと自体を目的化しない。

## Autonomy

実装を依頼されたら、最初の patch でレビュー待ちにせず、下記の Done を満たすところまで進めます。

- ローカルの読み取り、編集、差分確認、影響範囲に比例した test / lint / type check / build は、各段階で承認を取り直さず実行してよい。
- 自分の変更が原因の失敗は、原因を修正して影響する検証を再実行する。
- ユーザー確認で停止するのは、受け入れ条件を変える重要な曖昧さ、未承認の外部副作用、権限不足、安全上の制約、または実装だけでは解消できない blocker がある場合に限る。

## Done

タスクは次をすべて満たしたときに完了です。

- 依頼された観測可能な成果が実装されている。
- 明示された受け入れ条件をすべて満たしている。
- 変更に関連する検証が成功している。実行不能な検証がある場合は、その理由と残るリスクが明示されている。
- 変更した挙動が durable specification を変える場合、正本の仕様も整合している。
- 自分の変更による既知の回帰や未解決エラーを残していない。
- GitHub への反映が依頼に含まれる場合、要求された branch / commit / PR と期待される CI 状態まで確認している。

検証だけが成功して成果が未達なら Done ではありません。不要な追加作業で scope を広げることも Done の条件ではありません。
