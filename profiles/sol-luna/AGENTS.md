# GPT-5.6 Sol / Luna profile

GPT-5.6 Sol または GPT-5.6 Luna で作業するときだけ使用するモデル固有ガイダンスです。

## Model routing

- 既定: `gpt-5.6-sol / medium` — 実装、設計、デバッグ、レビュー、最終統合。
- 限定 worker: `gpt-5.6-luna / max` — 候補抽出、機械的変換、限定探索、独立した読み取り中心の確認。
- Luna が受け入れ条件を満たさない、または局所探索を越える判断が必要なら、同じ失敗を反復せず証拠を短く引き継いで Sol へ昇格する。
- 追加の routing 分岐は、ユーザー指定または repo-local eval で利用枠・速度・品質の測定可能な改善が確認された場合だけ導入する。

## Workflow

1. 目的、制約、受け入れ条件、変更対象を短く整理する。
2. 実装方針または完了判定を変える重要な曖昧さがあれば確認する。
3. 関連する仕様、対象コード、近傍テスト、必要な設定だけを読む。
4. 最小の変更を実装する。
5. 変更に比例した test / lint / type check / build / manual check を実行し、自分の変更が原因の失敗を修正する。
6. GitHub への反映が依頼に含まれる場合は、remote state と GitHub Actions の結果を確認する。
7. 受け入れ条件ごとに、成果と証拠が対応していることを確認して完了判定する。

## Done

- 依頼された成果が存在する。
- 必須の受け入れ条件がすべて満たされる。
- 関連する検証が成功するか、実行不能なものが blocker として明示される。
- 未解決の関連 failure を成功扱いしない。
- GitHub 反映が依頼された場合は、要求された remote artifact と CI 状態を確認済みである。
